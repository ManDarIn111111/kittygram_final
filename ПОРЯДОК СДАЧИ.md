# Практическая работа 4

## Локальная демонстрация

1. Открыть Docker Desktop.
2. В терминале перейти в папку проекта и выполнить `docker compose up -d --build`.
3. Открыть http://localhost:9000. Зарегистрироваться, войти, добавить котика с фото, изменить карточку.
4. Показать `docker compose ps -a`: db и backend healthy, gateway running, frontend Exited (0). Фронтенд завершает копирование сборки — это штатное поведение.
5. Показать тесты командами из README.
6. Выполнить `docker compose down`, затем `docker compose up -d`. Проверить, что карточка и фото сохранились.

## После самостоятельной загрузки на GitHub

В Settings → Secrets and variables → Actions добавить Variable DOCKERHUB_USERNAME и Secrets DOCKERHUB_TOKEN, TELEGRAM_TOKEN, TELEGRAM_TO. Токен Docker Hub должен разрешать запись. Боту предварительно отправить сообщение.

При push в main запускаются тесты и, после их успеха, публикация трёх образов. После публикации приходит уведомление Telegram. На pull request выполняются только проверки. Workflow не разворачивает проект на удалённом сервере.

Для полной сдачи показать зелёный запуск Actions и три образа в Docker Hub. До настройки аккаунтов эти пункты не проверены.

## Проверки исходного учебного репозитория

В папке tests сохранены оригинальные проверки. Часть требует публичные адреса Kittygram и Taski, Docker Hub и файл tests.yml. Они не являются локальными API-тестами. Образец tests.yml.example заполняется только реальными данными после публикации. Методичка отдельно требует работоспособность на localhost; требования GitHub и Docker Hub также сохраняются.

Маршрут /kittygram перенаправляет на корень сайта. Размещение вместе с Taski на отдельном сервере требует домена, настроек внешнего Nginx и отдельной проверки.
